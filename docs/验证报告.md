# 共著 0.1.0 验证报告

验证日期：2026-10-12。结论：已交付可在本机独立运行的 Windows x64 首版、安装包、源码和中文说明。软件流程测试通过；真实商业模型生成、Brave 在线搜索及全新电脑安装验收尚未完成。

## 环境与测试方式

- Windows x64，系统版本 10.0.26200。
- 最终应用运行时为 Electron 44.7.0，内置 Node.js 24.21.0 和 SQLite 3.53.4。
- 开发使用 Node.js 22.23.2；安装后的应用不依赖开发用 Node、Python、Office 或外部数据库。
- Vitest 核心测试 33 项通过。Playwright 桌面场景 2 项通过，并在 `release/win-unpacked/共著.exe` 上运行过同一套场景。
- 模型测试使用明确标记的模拟响应及本机 HTTP SSE 服务，不调用付费模型，不用固定样稿冒充真实 AI 创作。

## 容量测试

使用 400 章、1,054,800 个非空白字符的合成压力样本，在打包程序中导入、加载、检索和导出。章节列表不携带整章正文，只在打开章节时读取内容。

最终一次运行记录如下，原始数据见 `verification/capacity-report.json`：

| 操作                  |   本机实测 |
| --------------------- | ---------: |
| 启动打包程序          |   965 毫秒 |
| 导入 400 章           |  约 2.9 秒 |
| 加载章节目录          |    38 毫秒 |
| 定位第 400 章唯一标记 |     3 毫秒 |
| TXT 导出              |    42 毫秒 |
| DOCX 导出             |  约 1.1 秒 |
| PDF 导出并合并        | 约 16.2 秒 |

DOCX 和 TXT 逐章检查正文完整性；PDF 共 1600 页，提取全文后确认 400 章的开头与结尾标记全部存在。样本使用重复短段落，因此文件压缩率、页数和检索速度不能代表所有真实小说，也不是跨机器性能承诺。

## 文档与界面目视检查

- 实际打开模拟短篇 DOCX：通过本机 Microsoft Word 16.0 以只读方式打开，重新分页并渲染为 PDF，得到 15 页。检查正文页和末页，中文、段落、标题和页码正常。
- 应用直接导出的短篇 PDF 为 13 页。渲染并检查首尾页面，未见乱码、遮挡或页码缺失。
- 百万字 PDF 抽查第 1、801、1600 页，页码连续，末章末尾标记存在；没有逐页人工查看全部 1600 页。
- 桌面截图覆盖书架、编辑器、模型配置、参考库、模板和百万字目录。样稿是功能验收文本，重复句子是测试夹具，不能据此评价模型文学质量。

## 交付物

- `release/Gongzhuo-Setup-0.1.0.exe`：Windows x64 NSIS 安装包，可选择安装位置。
- `release/win-unpacked/共著.exe`：完整应用目录中的启动程序。移动使用时必须保留整个目录，不能只复制 EXE。
- `release/Gongzhuo-Source-0.1.0.zip`：源码、锁定依赖、测试、构建脚本、图标、说明和验证记录，不含 node_modules、密钥或作品数据库。
- `docs/使用说明.md`：模型配置、创作、导入、参考学习、修订、费用、导出与恢复说明。
- `release/SHA256SUMS.txt`：最终交付文件哈希。

## 尚未完成的验收及使用边界

1. 没有获得用户的商业 API 与 Brave 密钥，未执行真实五章长篇、真实八千字短篇或实际 Brave 搜索。适配器和流程测试通过不等于每家服务商的每个模型均兼容；需要在设置中测试实际端点。
2. 未在无开发环境的另一台电脑或干净虚拟机上实际安装、卸载和测试系统升级路径。已验证本机打包程序独立运行，不能把这一点写成干净机器安装已通过。
3. 当前交付未使用商业代码签名证书，安装包与应用显示未签名。没有修改、关闭或绕过 Windows 安全保护。
4. 自动审稿、记忆提取、原作元素隔离和作品质量仍依赖所选模型及人工检查；不会承诺过审等于没有逻辑问题或能成为爆款。
5. DOCX 导入保留文字、标题和段落，不支持复杂图文排版还原；网页读取不处理登录、付费或需要执行脚本才能出现的正文。
6. 同一备份中的既有作品不会被覆盖恢复。恢复到新的数据目录后，需要重新配置模型和角色。

## 复现命令

```powershell
npm ci
node node_modules/electron/install.js
npm run typecheck
npm test
npm run test:e2e
npm run package
npm run verify:capacity

# 用最终打包程序运行桌面场景
$env:STUDIO_ELECTRON_PATH = (Resolve-Path 'release/win-unpacked/共著.exe').Path
node scripts/test-e2e.mjs
```

`scripts/test-e2e.mjs` 将测试源文件复制到临时目录，解决 OneDrive 文件被标为重解析点时 Playwright 跳过测试的问题。测试使用独立临时数据目录，不触碰默认作品库。

`scripts/verify-word.ps1` 需要本机 Word，仅用于交付验证；`scripts/verify-pdf.py` 需要 pypdfium2。应用本身不依赖这两项。

协议实现参考官方文档：[Brave Web Search](https://api-dashboard.search.brave.com/app/documentation/web-search/query)、[Gemini GenerateContent](https://ai.google.dev/api/generate-content)、[Anthropic 流式响应](https://platform.claude.com/docs/en/build-with-claude/streaming)。
