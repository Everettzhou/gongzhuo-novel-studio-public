# 共著使用说明

## 安装与数据位置

运行安装包，选择安装目录并完成安装。安装后直接双击桌面的「共著」。不需要另外安装 Node.js、Python、数据库或 Office。打开 Word 文件可以使用 Word 或 WPS；生成 Word 文件不依赖它们。

运行数据默认在 `%LOCALAPPDATA%\Gongzhuo`。在「模型与设置 → 打开数据目录」可以找到。请使用应用里的项目备份功能，不要在程序运行时只复制数据库主文件，因为尚未合并的数据可能在 WAL 文件中。

应用没有内置商业 API 密钥。系统若显示应用发布者未知，是因为首版尚未签署商业代码签名证书；不要为运行应用关闭系统安全保护。

## 添加模型

点击「模型与设置 → 添加模型」。

| 字段            | 如何填写                                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 显示名称        | 自己容易识别的名字，如“主笔模型”                                                                                                |
| 接口协议        | 选择服务商实际提供的协议                                                                                                        |
| Base URL        | OpenAI 兼容接口填写 `/chat/completions` 之前的根地址；Anthropic 填 `/messages` 之前的根地址；Gemini 填 `/models` 之前的版本路径 |
| 模型 ID         | 服务商 API 文档或控制台给出的实际名称，不是网站聊天窗口标题                                                                     |
| API 密钥        | 该 API 服务的密钥，聊天网页会员不一定包含 API 额度                                                                              |
| 上下文/输出限制 | 按服务商模型实际能力填写；预留输入和输出空间                                                                                    |
| 价格            | 可不填；填写时统一币种，单位是每百万 Token                                                                                      |

保存后点击「测试连接」。这是一次真实的短 API 调用，可能计费。接口无法连接时检查模型名称、协议、地址、密钥和网络。

一个连接可以承担多个角色；同一个服务也可以添加多个不同模型连接。编辑密钥时留空表示沿用已有密钥。删除模型配置后，作品中原有角色需要重新绑定。

## 长篇连载

1. 点击「长篇连载」，填写作品名称、创意、题材与目标字数。
2. 在创作配置中选择策划、主笔和一到两个审稿模型。
3. 可补充目标读者、语言风格、禁区、角色提示词和已有大纲。
4. 默认每批五章，每章目标三千字；按需要修改。
5. 点击「自动创作」。策划生成批次计划，主笔分场景写作，审稿 AI 检查并交换意见，之后自动修订和复核。

自动生成时界面会展示草稿流和讨论记录。正文通过审查后标为正式，并维护章节和卷级记忆。应用不要求先一次性生成数百章细纲，而是按批次展开。

角色配置或正文修改会暂停正在运行的任务。底部可继续、取消或调整请求上限；右侧「任务历史」可以恢复更早的暂停任务。模型始终无法解决的严重冲突会停下来，等待你修改或调整模型后继续。

## 短篇小说

创建时选择「短篇小说」，默认八千字，可设为三千到两万字。应用会规划核心冲突与结局，分场景写出正文，然后进行全篇或分段加整体复核。

短篇显示为完整正文，不要求分卷。字数是目标而非严格计数约束；偏离目标超过 20% 时会要求修订，仍未达成时暂停，避免把明显不足的内容当作完成。

## 导入已有小说

进入作品，点击「导入」，选择 TXT 或 DOCX。TXT 支持 UTF-8、UTF-16 及 GB18030 回退。DOCX 提取标题、文字和段落，不还原图文、表格、批注或复杂版式。

导入预览中可以修改每段标题和文字，并合并相邻章节。确认后保存为正式正文；若已配置策划模型，自动提取摘要和设定。未配置模型时仍可正常编辑，之后在「设定记忆 → 更新摘要与后文影响」补建记忆。

## 学习参考作品

可采用以下方式：

- 粘贴文本，选择实际范围是全文、节选还是简介。
- 导入自己的 TXT/DOCX。
- 输入公开网页链接，提取当前页面正文。
- 配置 Brave Search 密钥后，输入题材和偏好，搜索候选或自动搜索并学习。

自动搜索可按最近一天、一周、一个月或一年筛选，最多发起三个查询，最多保留十个候选，自动学习最多三份能取得正文的资料。搜索和读取过程可以暂停、继续或取消，历史任务会保留候选、失败原因和实际读取范围。参考网页只取得当前页面，不自动追爬整本小说。需要登录、付费或动态页面无法提取时，可改用手动导入。

搜索结果不自动等于“爆款”。如果有真实榜单、热度指标和日期，在参考作品卡中记录；没有证据时按普通相关参考处理。

选择一个策划模型、勾选一至三份资料，点击「学习选中资料」。学习后会保存分析和写作模板。模型是在本次任务中分析资料并积累方法，不是在训练或修改模型参数。

在作品的「创作配置」勾选模板，分别调整结构、节奏和语言特征的参考强度。新故事会应用方法，原作人物和专有设定不会写入当前故事记忆。参考正文、分析和模板可独立查看、修改、删除及读取历史版本。

## 选区修改、记忆与后文影响

选中文字后，在右侧「修改建议」输入要求，如“增强紧张感，但不改变人物立场”。等待模型生成，比较原文和建议，选择采纳或拒绝。

建议绑定生成时的正文版本。如果你已改动正文，旧建议会失效，需要重新生成，避免误覆盖。接受建议后会自动更新本章摘要，并检查后续章节的潜在影响。涉及其他章节的修复必须由你确认，修订仍保存原版本。

手动编辑会使旧摘要失效。可点击「更新摘要与后文影响」立即处理，也会在下一次创作需要时重建相关记忆。点击设定可以修改内容、设置别名、标注未来计划或锁定；锁定内容是明确约束。

编辑器约一秒自动保存；切换作品、导出和正常关闭时会先保存。右上角的版本历史可查看旧稿，并恢复为新版本，不删除原有历史。

## 暂停、费用和错误处理

默认每次任务最多一百次模型请求，重试也计数，同时最多三个请求。底部齿轮可调整请求次数和可选费用上限。

启用费用上限前，所有参与模型都需要填写同币种价格。输入 Token 通常只能预估；费用预留按输入估算加输出上限计算，响应后按服务商用量调整。没有价格时显示“费用未知”，并继续执行请求次数限制。失败请求可能已经计费，因此保守保留预估费用。

| 情况                 | 处理方式                         |
| -------------------- | -------------------------------- |
| 密钥错误、余额不足   | 修改配置或充值后继续             |
| 限流、临时网络错误   | 最多自动重试两次，仍失败则暂停   |
| 达到请求/费用上限    | 调整上限后恢复原任务             |
| 输出被截断           | 草稿保留，增加模型输出限制后继续 |
| 结构化结果不合格     | 自动要求补正一次，仍失败则暂停   |
| 两轮修订仍有严重问题 | 查看证据，人工修改后复核         |
| 程序退出或重启       | 保存进度，重启后由你恢复         |

点击底部任务状态可查看任务详情和中断草稿；中断输出不会自动混入正式正文。写作、参考搜索学习、记忆重建、选区改写和已确认的跨章修复均可恢复。若选区对应正文或已确认修复的前文再次发生修改，旧任务会拒绝覆盖，需要重新选择或确认范围。参考页通过任务历史下拉框恢复之前的学习任务。

## 导出与备份

导出支持全书、分卷、当前章节或勾选指定章节，仅包含正式正文。手写内容可在编辑器底部点击「草稿 · 标为正式」后导出。

- DOCX：书名、简介、标题、段落和页码。
- PDF：本地中文排版，A4；大作品分段生成并合并，页码连续。
- TXT：UTF-8，保留标题和正文。

项目备份包含作品、版本、设定、讨论、参考和模板，不含密钥及模型连接。恢复不会覆盖重复的作品 ID，需要在新的数据目录恢复已有作品的同一份备份；恢复后重新配置模型和角色。
