# 共著 0.2.0：写作 Skills 与复盘更新

## 使用方法
1. 安装 Gongzhuo-Setup-0.2.0.exe，进入「模型与设置 → 写作 Skills 库」。
2. 选择 UTF-8 的 SKILL.md、其他 Markdown 或 TXT 文件，预览并保存。每个文件最多 100 KB，指令正文最多 24000 字符。只读取选择的指令正文，不读取 Skill 目录中的关联资料，不执行脚本。
3. 打开作品「创作配置 → 写作 Skills」，分别为策划、主笔、审稿选择所需 Skill，每个角色最多 5 个。两个审稿 AI 共用审稿 Skills；同一个模型可以承担不同角色，各角色指令相互隔离。
4. 写作时，已启用 Skill 会随对应步骤发送给模型，讨论记录标注 Skill 名称与版本。适用于大纲、场景正文、审稿/全篇复核、主笔回应、修订、选区改写和后文修复。事实提取、摘要维护及独立参考分析不注入写作 Skills。

## 从写作过程生成与更新 Skills
在 Skills 库选择「复盘作品」，选择「生成新的 Skill」或已有更新目标，点击「从写作记录提炼 Skill」。

- 策划模型分析最近 5 章的有效摘要和开头节选（每章开头最多 1200 字符），以及最近 8 条讨论（每条最多 1200 字符）。这是有限样本复盘，不是自动通读全书。
- 模型返回完整 Skill 指令、修改理由、局限与来源记录 ID；应用校验 ID，保存当时的样本、章节版本和原 Skill 内容。
- 在「待采纳」展开更新前后对照，选择采纳或拒绝。已有 Skill 采纳后生成新版本，旧版本保留在本地版本库；已绑定该 Skill 的作品后续调用使用新版。新 Skill 需手动绑定角色。
- 并非后台无人值守训练或自动覆盖：复盘由用户点击触发，规则变更由用户采纳。当前版本没有训练模型权重，也没有自动评估 Skill 效果；建议先试写比较。
- 复盘任务支持暂停、取消及重启恢复，可在对应作品任务栏操作。失败或超上下文时保留记录，调整后继续。已有 Skill 在提议后被用户编辑，采纳旧建议会提示版本冲突。
- Skills、历史版本和复盘建议随项目备份保存；在线模型调用会发送本次所需内容。API 密钥不进入项目备份。

## 示例 SKILL.md
```markdown
---
name: 冲突与悬念
description: 用于小说场景写作和修订
---
先明确本场景人物想要什么，以及阻止其达成目标的障碍。
使用可观察的行动与细节表现冲突，避免连续解释动机。
场景转折必须有此前证据或铺垫；结尾保留一个与主线相关的问题。
不为制造悬念改变作品已经锁定的事实。
```

## 验证口径
单元测试使用模拟模型验证实际请求消息、版本、证据与持久化；桌面测试使用本机模拟 SSE API。商业模型生成质量、真实费用以及新 Skill 对小说质量的提升需要用户配置 API 后试读比较。
旧版 0.1.0 安装包保留。0.2.0 使用原有本地数据目录，旧作品没有 Skills 绑定时行为保持不变。
